# 可选细话题实施计划

1. 扩展领域模型与结构化输出 Schema：在生成话题下接受可选 `subtopics`，规范化时只保留父范围
   内且字段有效的条目，把非法条目记录为非阻断诊断；保持旧 JSON 兼容。
2. 增加细话题提案与批准集合的 SQLite 表和 Alembic 迁移，实现按文章版本创建草案、校验、批准、
   替换和查询当前集合的普通 Python 服务函数。
3. 扩展联合分块 Prompt、审核 JSON 与现有审核页：新文章可查看、编辑、删除和新增三字段细话题；
   批准分块时同时批准有效补充，空集合不阻断。
4. 为既有批准文章增加只提取细话题的 Codex 结构化 Prompt 与单篇生成入口，复用当前
   `CodexCliClient`、外发披露和确认边界，不允许修改父话题。
5. 增加独立细话题审核服务与语料管理页“补充细话题”操作，支持未补充、待审核、已批准状态；
   批准后只调用文章索引构建器。
6. 升级文章检索 Profile，把批准细话题标题和概括加入文章检索文档，并在结果中返回匹配细话题；
   保留旧 Build 可复现。
7. 使用自造短文本补齐领域、迁移、联合生成、补充生成、审核 HTTP、文章索引和失败回滚测试，
   同步 README、架构、分块索引和 CLI 指南。
8. 运行 Ruff、Pyright、完整 pytest 与 `git diff --check`；最后通过现有 Codex 单篇披露确认流程，
   对一篇用户明确选择的本地长文完成一次真实生成验收；标题和结果不得进入公开仓库。
