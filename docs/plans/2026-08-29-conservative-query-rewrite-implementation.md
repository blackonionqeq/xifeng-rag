# 保守查询改写与多查询融合实施计划

对应设计：[`docs/specs/2026-08-29-conservative-query-rewrite-design.md`](../specs/2026-08-29-conservative-query-rewrite-design.md)

## 交付顺序

1. 扩展配置与领域模型，增加 Query Rewrite provider、最大变体数、原问题权重、改写总权重、
   结构化改写结果及候选的查询来源排名；默认配置不启用改写。
2. 新建边界清晰的查询改写模块，定义普通 `QueryRewriter` 接口、`NoopQueryRewriter`、输出
   过滤和配置校验；使用自造问题覆盖空文本、重复、超量和部分成功。
3. 基于现有 Ollama 客户端模式实现 `OllamaQueryRewriter`，只发送当前问题，要求 JSON Schema
   输出并施加保守改写 Prompt；服务不可用、超时或无有效结果时返回可诊断失败，不外发、不读取
   语料，也不阻断原问题检索。
4. 将默认与分层检索拆出“召回候选”和“最终重排”边界；旧公开搜索函数保持原行为。新增
   Retrieval Profile 无关的多查询编排：各变体只召回，按候选 ID 去重，以原问题 1.0 和固定
   改写总权重执行查询级加权 RRF，限制候选并集后用“原问题为主、改写辅助”的组合查询只重排
   一次。
5. 给 `search`、`ask` 和 `eval run` 增加显式 `--rewrite`；CLI 根据配置工厂选择改写器，关闭
   开关时不启动 Ollama。结构化输出保留改写状态、有效变体、各变体命中排名和查询级融合排名。
6. 扩展评测运行配置与逐题详情，支持 TopicChunk/分层检索各自的无改写与有改写对照，并记录
   正确证据排名变化、改写状态、模型与 Prompt 版本、改写延迟和总延迟；保持旧评测记录可读。
7. 覆盖接口替换、保守输出过滤、Ollama payload、失败回退、固定总权重、稳定融合、单次重排、
   两种 Retrieval Profile、CLI 开关、评测元数据和默认无网络路径；更新 README、示例配置及职责
   匹配的设计文档。
8. 运行 pytest、Ruff、Pyright、`git diff --check` 和 CLI smoke test；随后用本地 Ollama 在现有
   6 题冻结试验集上完成四组冒烟对照，并单独复测“作者职业身份变化”案例。提升、退化和新增
   延迟均写回设计记录，不据单个案例切换默认路径。

## 实现边界

- 第一版只实现同义且约束显式化的查询改写，不实现拆解、HyDE、候选反馈、充分性判断或路由。
- `QueryRewriter` 是显式配置选择的普通接口，不加入动态发现、注册表或通用插件平台。
- 改写器只接收当前用户问题；原问题由编排层保留，任何实现都不能替换或修改它。
- 默认 provider 使用本地 Ollama；实现失败只退回原问题，绝不自动改用外部服务。
- 查询改写是查询时实验参数，不改变 Index Profile 身份，也不触发索引重建。
- 测试使用 Fake rewriter、embedding 和 reranker，不启动服务、不下载模型、不访问外部语料。
- 现有 `tempnpm-cache/` 属于无关未跟踪目录，不纳入任何提交。

## 完成门槛

- `--rewrite` 关闭时，现有 search/ask/eval 行为和排序不变，且不会创建 Ollama 客户端；
- Ollama 与 Noop 实现遵守同一输入输出契约，未来实现可通过配置工厂替换；
- 0 到 N 条有效改写均可运行，所有改写共享固定总权重，结果和稳定并列顺序可复现；
- 默认和分层 Profile 均经过“多查询召回一次融合、组合查询一次重排”，候选来源可审计；
- 无效输出、部分输出、超时和本地服务不可用均回退原问题，不产生外部请求或正文日志；
- 自动测试、Ruff、Pyright 和 CLI smoke test 全部通过，真实 6 题试验可复现并完整报告成本与退化。
