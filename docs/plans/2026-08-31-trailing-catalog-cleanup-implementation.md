# 文末付费文章目录清洗加固实施计划

状态：已完成。

关联设计：[`docs/specs/2026-08-31-trailing-catalog-cleanup-design.md`](../specs/2026-08-31-trailing-catalog-cleanup-design.md)

## 目标

修复清洗器从后续子目录才开始截断的问题，使完整的文末付费文章目录在规范正文生成前被
确定性移除；低置信度案例进入人工清洗审核，残留可疑目录不得继续调用分块模型。

## 实施步骤

1. 在 `corpus.py` 中为原始行构造只用于检测的归一化视图，忽略 Markdown 强调符号并统计
   Markdown 链接、独立链接行及目录语义信号。
2. 将现有单点向后扫描替换为尾部目录区域分析：先确认高置信度链接目录，再回溯到连续区域内
   最早的目录引导语；不确定时返回待审核警告而不删除。
3. 提供只读的清洗对比数据结构和 CLI dry-run 入口，输出文章、判定、新旧截断范围与字符数，
   不修改 SQLite，也不输出正文或 URL。
4. 提升清洗器版本，确保后续正式 `corpus scan` 能为规范正文变化的文章创建新版本。
5. 在 `chunking.py` 中更新默认分块指令，并在模型调用前对已存规范正文做残留目录检查；命中时
   直接报错，避免模型生成混合话题。
6. 为粗体拆词、同行多链接、多账号连续目录、目录说明、普通单链接、短参考列表和正文恢复等
   情况增加合成测试；验证防线命中时生成器没有被调用。
7. 更新 README 与切块/索引设计中的命令和行为说明。
8. 对外部语料运行全量只读 dry-run，重点检查近期 5 篇都回溯到更早的完整目录入口，并检查
   其他自动截断与待审核结果是否异常。
9. 运行 Ruff、Pyright、完整 pytest 与 `git diff --check`，提交实现。

## 完成条件

- 近期 5 篇的目录都不再出现在新规范正文中；
- 高置信度自动删除仅由目录语义、链接结构和尾部连续性共同触发；
- 不确定案例不会继续分块；
- dry-run 无数据库写入且不显示正文或 URL；
- 自动化检查全部通过。
