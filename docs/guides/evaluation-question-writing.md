# 评测问题编写与 AI 草案审核指南

本指南用于 `xifeng eval curate` 的人工出题和审核。目标不是制作阅读理解作文题，
而是建立边界清楚、证据稳定、能够判断检索质量的金标准问题。

## 先判断问题是否适合评测

一条合格问题通常同时满足以下条件：

- 它像真实使用者会提出的信息需求，而不是为了命中某个词设计的题目；
- 当前选择的一篇文章能够独立回答；
- 什么算答对、哪些内容属于题外，可以事先说清楚；
- 主要答案能拆成一至三个独立要点；
- 直接证据集中，通常能被不超过五个话题块覆盖；
- 与题集中已有问题相比，考查的信息需求或证据区域有明显区别。

一个实用的自检问题是：

> 如果两个人独立阅读文章，他们是否大概率会标出相近的答案要点和证据？

如果答案是否定的，这道题往往过于主观、宽泛或含有未说明的前提。

## 控制问题范围

V0 默认以 `top-k=5` 观察检索结果。问题不必机械地只对应五个段落，但不应要求系统在
全文十几个分散位置穷举信息。否则低分可能只是题目天然超出 Top-K 容量，而不是检索失败。

首批 pilot 推荐：

- 普通解释题包含一至两个答案要点；
- 有边界的综合题最多包含三个主要要点；
- 每个要点使用一至两个紧凑、直接的证据范围；
- 六至八道题尽量覆盖不同文章和不同证据区域；
- 全文多点综合题最多保留一道，用作高难度观察样本。

问题中的范围提示不等于泄露答案。例如“在作者讨论的三个交易观点中”是在限定范围，
通常优于“文章里所有提到时间的地方”。前者有稳定边界，后者会诱导模型做全文词语扫描。

## 当前评测中的“难”指什么

当前运行器评测的是检索，不评判最终生成答案的推理质量。它检查金标准证据块是否出现在
Top-K、首次命中的位置以及原子单元覆盖率。因此，答案需要一定推理的问题仍然有价值，
但它当前直接检验的是系统能否找回完成推理所需的证据。

有价值的难度来自：

- **词汇错位**：问题使用自然改写或同义表达，不直接复制原文关键词；
- **有限组合**：需要连接两至三个紧凑证据位置才能回答；
- **关系识别**：需要识别原因、条件、限制、对比或例证与结论之间的关系；
- **近义干扰**：语料中有相似词语或主题，但只有特定语境真正回答问题；
- **信息完整性**：既要找回主要结论，也要找回会改变结论强度的限制条件。

不应通过扩大到全文、增加未说明的前提、依赖外部知识或使用含糊指代来制造难度。
困难题也必须有清楚边界和稳定金标准。

## 难度配比

全是简单题容易产生天花板效应，不同检索方案都接近满分；全是困难题又容易产生地板效应，
不同方案都接近零分。两种情况都不利于比较。

首批六至八道 pilot 推荐：

- 两道简单题：问题与原文表述接近，用于确认基础检索正常；
- 三至四道中等题：包含自然改写或一个关系判断，证据集中在一至两个话题块；
- 一至两道困难题：需要组合两至三个证据位置，或排除语料中的相似干扰内容。

正式 benchmark 应继续保留难度混合，并分别观察简单、中等、困难题的结果，不能只看总体
平均分。当前数据结构尚未保存难度标签；pilot 阶段先人工控制题型分布，正式 benchmark
前再决定是否增加 `difficulty` 字段和分层指标。

## 推荐的困难题形式

### 不复用核心术语的自然改写

普通版本：

```text
沉没成本为什么会阻碍及时止损？
```

较难版本：

```text
为什么一个人即使已经意识到方向可能错误，也往往难以及时放弃此前投入很多的选择？
```

后者减少了与原文术语的直接重合，但仍然有明确答案。

### 两段关系组合

```text
作者为什么先介绍一种正向筛选方式，随后又描述普通参与者的反向操作？
这组对比想说明什么心理机制？
```

单独找到任意一段都不足以完整回答，但所需证据仍应控制在少数位置。

### 条件与限制组合

```text
作者建议采用某种做法时依赖哪些前提？哪些成本或条件会限制它的效果？
```

这种题可以检查系统是否只召回正面描述，却漏掉限制条件。

### 隐含但稳定的因果关系

```text
为什么作者认为投入越多，有时反而越难纠正错误选择？
```

文章未必用一句话写成“因为 A，所以 B”，但支持关系必须能由少量直接证据稳定推出。

### 有近义干扰的概念区分

```text
作者在这里讨论的“成本”主要指已经付出的投入，还是未来继续行动的代价？
这一区分如何影响决策？
```

难点应是找到正确语境，而不是猜测出题者心中的隐含定义。

## 避免“伪难题”

以下问题可能得分很低，但低分无法可靠说明检索系统较差：

- 要求枚举全文所有相关位置；
- 询问“作者真正想说什么”却没有限定主题；
- 依赖文章外理论、常识或个人价值判断；
- 一题同时包含五六个独立主题；
- 不同审核者会选择完全不同的标准答案；
- 故意省略关键对象，导致指代不明；
- 金标准证据天然需要超过 Top-K 的大量分散话题块。

提高难度的原则是：减少关键词重合，增加有限且可审核的关系组合；不要增加范围和歧义。

## 推荐的问题类型

### 原因或机制

```text
作者为什么认为……？其中的关键机制是什么？
```

### 条件与限制

```text
在什么条件下作者建议……？这项建议有哪些限制？
```

### 有边界的比较

```text
在文章讨论的两种做法中，作者如何比较它们的成本与收益？
```

### 有边界的综合

```text
在文章列出的三个主要观点中，某个因素分别扮演什么角色？
```

### 对明确论断的解释

```text
作者所说的“……”具体指什么？他用什么理由支持这一判断？
```

## 常见问题及改写方式

### 主观感受无法形成金标准

不推荐：

```text
这篇文章是不是信息量很大，因为里面有很多矛盾？
```

问题在于“信息量大”是个人感受，“因为”又预设了未经文章直接证明的因果关系。

可以改成：

```text
作者为什么认为实践中很难同时满足多个理想目标？他讨论了哪些具体取舍？
```

### 全文穷举导致证据过散

不推荐：

```text
文章里多次提到某个概念，分别是在说什么？
```

可以改成：

```text
在文章关于某一主题的三个主要观点中，这个概念分别起什么作用？
```

### 范围过大

不推荐：

```text
请总结这篇文章的全部观点。
```

可以改成：

```text
作者对某项具体选择给出了哪两个核心理由？
```

### 问题之间高度重复

如果两道题需要找回几乎相同的段落，即使措辞不同，也没有为评测集增加多少信息。
优先换文章、换证据区域，或者让新问题只考查其中一个尚未覆盖的机制。

### 用问题直接列完答案

范围提示可以出现，但不要把所有结论都写进问题。例如，与其问“作者是否认为 A 导致 B、
C 导致 D、E 导致 F”，不如限定章节或观点数量，让回答者自行提取关系。

## 审核 AI 参考答案

AI 输出只是候选。接受候选只会把它复制到人工草案，不代表完成审核。

参考答案应当：

- 直接回答问题，不先接受问题中未经证明的主观前提；
- 只使用所选文章的信息，不补充外部常识；
- 覆盖所有重要要点，但不扩展到问题范围之外；
- 保留作者使用的“可能”“通常”“在某些情况下”等限定；
- 使用简洁概括，不复制长篇原文；
- 避免把相关关系强化成因果，把建议强化成保证，把暂时缓解写成彻底解决。

如果答案包含“文章的信息量主要来自……”“作者写得好是因为……”之类效果判断，
应检查文章是否真的作出了该判断。多数情况下，这只是模型的读后推断，不宜进入金标准。

## 审核答案要点

每个答案要点应表达一个可以独立判断真假的主要结论。出现以下情况时应拆分：

- 一句话包含两个需要不同证据支撑的结论；
- 前半句可能正确、后半句可能错误；
- 同一要点跨越文章中相距很远的多个主题。

`claim_group` 只是简短稳定的分组名，例如“适用条件”“机会成本”“风险缓冲”，
不必写成完整句子。

参考答案中的每个重要结论都应能对应到一个答案要点；答案要点中也不应出现参考答案
没有回答、问题没有询问的额外主题。

## 审核证据范围

证据应当“最小充分”：

- **最小**：删除纯过渡句、重复例子和无关上下文后，仍能支持要点；
- **充分**：只看选中段落，读者也能合理得出该要点；
- **直接**：证据确实表达或论证该结论，而不只是出现相同关键词；
- **对应**：一个范围只属于当前文章版本，并与对应答案要点一致。

同一要点由两个不连续位置共同支持时，应添加两个范围，不要把中间大段无关内容一起选中。
如果必须选择大量分散范围才能支撑一个要点，优先缩小要点或改写问题。

证据审核的简易测试是：

> 只把这些证据交给另一个人，他能否在不依赖外部知识的情况下写出这个答案要点？

## “不确定性”应该记录什么

不确定性用于保存会影响结论强度或适用范围的信息，例如：

- 作者使用了“可能”“也许”“不见得”等保留措辞；
- 结论只适用于特定阶段、条件、对象或市场；
- 原文只说明相关性，没有明确说明因果性；
- 某项方法有成本、时效或可行性限制；
- 结论属于作者的经验判断，文章没有把它证明为普遍规律。

没有重要限制时可以留空或填写“无”。

以下内容通常不算不确定性：

- “这是作者的观点”；
- “这是文章的论证框架”；
- 对要点的重复解释；
- 用一句免责声明保留一个实际没有证据或明显过强的结论。

如果证据只支持较弱结论，应直接降低答案要点的断言强度，而不是依靠不确定性字段补救。

## 接受、修改还是拒绝 AI 候选

可以接受后微调：

- 回答方向正确，没有文章外信息；
- 要点基本完整，仅需调整措辞、限定词或证据边界。

建议大幅修改：

- 问题范围清楚，但 AI 漏掉一个核心要点；
- 多个结论混在一个要点中；
- 证据正确但选择范围明显过宽。

建议拒绝并先改问题：

- AI 必须猜测问题中的主观前提；
- 不同合理读者会给出完全不同的答案范围；
- 候选包含四五个以上分散主题；
- 证据数量明显超过当前 Top-K 能力；
- 新问题与已有问题使用几乎相同的答案和证据。

## 标记人工审核前的检查表

- 问题是一条真实、清楚、单篇可回答的信息需求；
- 问题没有预设文章无法证明的因果或评价；
- 参考答案直接回答问题，且没有文章外推断；
- 每个重要结论都对应一个原子化答案要点；
- 每个要点至少有一个直接、最小充分的证据范围；
- 作者的条件和保留措辞已反映在答案或不确定性中；
- 证据总量与当前 `top-k` 大致匹配；
- 这道题为题集增加了新的文章、主题、难度或证据区域；
- AI 候选已经由人逐项检查，而不是因为文字通顺就直接通过。

首批 pilot 的价值就在于发现坏题、过宽证据和审核流程问题。pilot 中改题并重新生成不是浪费，
而是在正式建立 dev/holdout benchmark 前校准标准。
