# 版本路线与实验方向

状态：路线基线 v0.3。V0 与 V1 单轮问答主链已实现；当前重点从增加能力转向扩大验证证据。

当前本地语料、活动索引和评测题集数量以数据库为准。在项目根目录运行
`uv run python scripts/current_status.py` 查询，不从本文的历史实验快照推断当前规模。
脚本分别报告已批准文章、可建索引的文章与话题块、活动索引快照一致性，以及题集数量。
pilot 结果只用于验证工作流、形成假设和定位失败案例，不支撑参数或模型的泛化结论。正式
benchmark 已冻结并完成首轮检索基线，但题量仍小，结论只适用于当前快照。

## 1. 版本路线

### V0：可用的 BM25 基线

状态：已完成。

- 确定性清洗语料，排除文末付费目录和推广区；
- 本地 AI 单层话题分块、概括与人工确认；
- 已批准话题块上的 BM25 检索；
- 稳定原文引用；
- 初始固定评测集；
- 记录 P@K、Recall@K、MRR、nDCG 和延迟。

V0 必须解决人工分块成本，同时提供可运行、可验证的检索基线。固定长度自动分块只作为后续实验对照，不要求用户手工切块。

评测集先通过 6–8 道单篇 `pilot` 题验证人工问题、Codex 候选、证据范围审核、冻结快照和
BM25 跑分闭环。pilot 只用于探索，不能原地升级为正式 holdout。用于面试展示的首版正式
benchmark 控制为 10 道：6 道单文章可回答 dev、2 道单文章可回答 holdout、2 道不可回答
holdout。金标准保存文章版本与原子单元范围，运行时动态映射 TopicChunk，并额外报告
evidence coverage@K。

### V1：混合检索主题研究台

状态：单轮问答主链、本地演示和项目控制台已完成；跨文章主题研究、真正的增量派生索引和
正式产品入口尚未完成。

- 本地 Embedding；
- Dense + BM25 + RRF；
- 本地 Reranker；
- DeepSeek V4 Flash Generator；
- 单篇问答，以及待正式验证的跨文章主题综合；
- 精确原文引用；
- 增量语料状态；向量与 BM25 的逐文章增量更新后续实现。

### V1.x：重点优化实验

状态：分层子块检索、保守查询改写和证据观测层已经实现为显式实验；是否默认启用必须等待
正式 benchmark 结果。

优先研究：

1. 话题块原文与 AI 上下文化索引文本对比；
2. 不同本地 Embedding 模型对比；
3. 无重排与不同本地 Reranker 对比；
4. TopicChunk、确定性子块、父子并行召回及相邻扩展的 A/B/C/D 对比；
5. DeepSeek Generator 的提示词、忠实度、完整性和延迟分析；
6. AI 话题长块、固定长度小块和父子分块对比。
7. Reranker 后证据充分度信号观测，以及证据不足时分层补检索的降级假设。

第一阶段的本地模型只负责离线语义分块、概括和显式启用的保守查询改写。后续再研究更完整的
Contextual Retrieval，以及本地/外部 Generator 对比。HyDE、RAPTOR、上下文压缩、Self-RAG
等方法先列为候选，不在正式 benchmark 建立前继续扩张主线。查询改写设计见
[查询改写设计](../specs/2026-08-29-conservative-query-rewrite-design.md)。

### 当前后续顺序

1. 10 道首版正式 benchmark 已完成并冻结：6 道单文章可回答 dev、2 道单文章可回答 holdout、
   2 道不可回答 holdout。当前不加入跨文章题。题目保存检索难度，并以 `legacy_seen`、`new_dev`、
   `new_holdout` 区分用途；运行结果按 split、难度和来源分组。
2. 独立的“主题反查文章”累计索引、三模式评测，以及概括/关键词/细话题/原文四层隔离实验与
   降级重放已跑通；早期 6 道真实题上的 `disagreement_cascade` 结果只是临时默认策略的
   开发依据。继续自然积累问题；阈值与“细话题优先”顺序须在扩大的 dev 上验证。
3. 端到端回答与引用评测命令已经实现并完成首轮 dev 基线；下一步根据 dev 中的多余引用和
   上下文成本决定是否调整，再显式运行 holdout。第一版采用确定性状态、引用和证据范围指标，
   不引入自动语义裁判或新的人工评分页面；设计见
   [端到端回答与引用评测设计](../specs/2026-10-19-end-to-end-answer-evaluation-design.md)。
4. 评测工作台已经支持对冻结题集运行本地检索评测、查看汇总与逐题失败，并在题集哈希、语料
   快照、split 和 K 兼容时对比历史基线；holdout 运行需要额外确认。端到端回答评测仍保持独立。
5. 本地面试演示入口已经实现，集中展示文章反查、证据披露、回答与引用核验；项目控制台集中
   启动演示、语料管理和评测工作台，并提供常用命令速查。公开演示仍应换用自造短文本语料。
6. 基于扩大后的 dev 集验证证据观测信号；需要补检索时优先研究 TopicChunk 与分层结果的
   比较或合并，不用单一绝对阈值直接替换结果。正向证据检索的细话题召回通道
   （`eval run --subtopics`）已在 pilot 6 题上实验并得到负结果（提名父块结构整体退化，
   不默认启用），设计见[正查细话题召回通道设计](../specs/2026-09-03-subtopic-recall-channel-design.md)；
   复验或改结构须在扩大的 dev 集上进行。
7. 随语料规模扩大，实现向量与 BM25 派生产物的逐文章增量构建和原子切换。
8. 验证跨文章主题综合与时间变化，再建设 FastAPI 和正式 Svelte 研究界面。
9. 在正式 dev 集上按单变量原则比较 contextual text、Embedding、Reranker、切块和预算；
   GraphRAG、HyDE、RAPTOR、压缩与 Self-RAG 保持后置。

### V2：图增强 RAG

增加主题、观点、论据、文章和时间等节点与关系。图检索输出与现有检索候选相同的统一结构，然后进入融合、重排和生成流程。

至少比较：

- Vector-only；
- Graph-only；
- Vector + Graph。

重点验证跨文章观点综合、观点演变和潜在矛盾，而不是预设 GraphRAG 必然在所有题型上更好。

## 2. 固定评测集

面试展示版先冻结 10 道高质量问题，其中 6 道作为开发集，4 道作为阶段性保留集；后者包含
2 道可回答题和 2 道不可回答题。当前只评单文章问题，成熟后再按实际实验需求扩充。可回答题
必须标注相关文章及支持段落。题型包括：

- 单篇事实；
- 单篇观点；
- 语料证据不足、系统应明确拒答的问题。

评测集采用“人工主导、强 API 辅助”的方式：用户先提供 5–8 个真实问题；外部 API 针对用户显式选择并确认的少量清洗后完整文章生成候选问题、参考答案、关键得分点和支持段落；用户审核修改后才进入冻结评测集。出题时不得提供现有检索结果，避免围绕当前系统能力倒推容易题。

生成评测集的 API 模型尽量与回答阶段的 `deepseek-v4-flash` 不同。若使用同一模型，检索指标仍以人工确认的支持段落为准。项目保存模型、Prompt 版本、文章哈希和人工修改记录，但不把外发的完整付费正文写入普通日志。

通用题集用于所有版本公平比较。图谱优势题集单独报告，避免通过选择题型人为抬高 V2 总分。

## 3. 评测维度

### 检索

- Precision@K；
- Recall@K；
- MRR；
- nDCG。
- 查询改写前后每题证据排名变化、无效改写率与改写失败率。

### 引用

- 引用命中率；
- 关键结论的引用覆盖率；
- 引用是否真实支持对应结论。

### 回答

- 忠实度；
- 问题相关性；
- 跨文章信息完整性；
- 人工偏好与失败类型。

### 工程

- 全量索引耗时；
- 新增单篇文章的增量耗时；
- 查询延迟；
- 查询改写延迟及其占总延迟的比例；
- 显存与内存占用。

## 4. 实验纪律

- 使用冻结的语料快照和评测集比较版本。
- 单变量实验只改变一个组件或配置。
- 保存模型、Prompt、索引 profile、代码和硬件信息。
- 自动评委只作为辅助，关键结果保留人工核验。
- 同时报告提升、退化、成本和失败案例，不只展示最高总分。

这样的项目叙事重点是“提出假设、设计对照、获得证据并解释结果”，而不是堆叠尽可能多的 RAG 名词。
