# 分层文章反查与降级策略实验设计

状态：已确认，2026-09-02。

## 1. 目标

把文章反查从“全部字段拼成一份文章文档”拆成由粗到细的独立检索层，先在相同题集和语料快照
上完整记录每层结果，再离线比较聚合与降级策略。实验要回答：不同记忆粒度的问题分别适合哪一
层，以及何种可观测信号足以触发下一层，而不是预先假定某个固定阈值有效。

本阶段不实现线上自动降级，不把各层内容重新拼成长文档，也不根据当前 5 道开发题调整生成
内容。现有题只用于验证实验闭环和形成假设；正式结论必须等待扩大后的 dev 与 holdout。

## 2. 四个隔离检索层

标题作为各层共同且受控的文章标识信息；除此之外，每层只消费自己的内容，不读取其他层字段。

### 2.1 概括层

每篇文章一个检索文档：

```text
文章标题 + 已批准文章概括
```

用于覆盖文章核心判断、主要论证路径和模糊主题记忆。该层不加入父话题、关键词、细话题或
原文。

### 2.2 关键词层

每篇文章一个检索文档：

```text
文章标题 + 已批准父话题标题 + 去重补充关键词
```

该层不加入文章概括、细话题或原文。BM25 是主要假设，Dense 仍保留为实验通道，以实际结果
判断短语集合是否有稳定语义召回价值。

### 2.3 细话题层

每个已批准细话题形成一个独立检索单元：

```text
文章标题 + 父话题标题 + 细话题标题 + 细话题概括
```

检索单元携带文章、版本、父话题和细话题范围，命中后聚合回文章。不得把所有细话题拼进一个
文章向量，也不得把细话题概括作为作者原话或回答证据。

该层不设置父话题级或文章级细话题业务数量上限；生成阶段只要求保留有检索辨识度并合并相似
候选，结构化 Schema 仍以每父话题最多 20 个防止异常输出。索引和检索阶段不得再次截断已经
批准的细话题集合。没有已批准细话题的文章在该层记为不可用，不得用其他字段静默回填。

### 2.4 原文层

使用已批准且 `include_in_index=true` 的规范正文范围，在现有 TopicChunk 内确定性派生较小原文
单元；不把整篇长文编码为单个 Dense 向量。检索单元携带文章、版本、父话题、原子单元范围和
`original_text`，命中后聚合回文章。

该层只用于文章发现实验。若后续展示证据，引用仍必须经过现有原文引用链，不能直接把文章聚合
结果当作已选证据。

## 3. 检索与文章聚合

四层分别运行 BM25 与 Dense，首轮不做跨层融合。概括层和关键词层是一篇文章一个文档，可直接
得到文章排名；细话题层和原文层是一篇文章多个检索单元，必须比较以下聚合方法：

1. `best_unit`：使用文章最佳命中单元的分数或排名；
2. `top_n_rank_fusion`：每篇文章最多取排名最高的 3 个单元，以固定 `rrf_k` 汇总排名贡献。

`best_unit` 是首要基线，便于回答“只要命中一个记忆点能否找回文章”。`top_n_rank_fusion` 用于
观察多处弱命中是否可靠，但必须把单篇贡献限制为 3 个，避免长文章仅凭单元数量占优。

每次运行同时记录每篇文章在细话题层和原文层的可检索单元数。报告指标时按单元数分组检查排名
和误召回，显式暴露长文章的“多入口偏置”。不同层、不同检索器的原始分数尺度不可直接相加或
共用绝对阈值。

## 4. 运行记录

每道题、每层、每种检索模式和聚合方法至少保存：

- Top-K 文章、文章排名和对应聚合分数；
- 正确文章排名与 reciprocal rank；
- 最佳命中单元的类型、稳定 ID、父话题和原子单元范围；
- BM25 分数或 Dense 相似度，以及单元检索原始排名；
- Top1 与 Top2 的层内分数差、比值和排名差；
- BM25 与 Dense 的 Top1/Top-K 文章一致性；
- 该文章在当前层的可检索单元数；
- 检索和聚合延迟；
- Build、Profile、语料快照、题集哈希、模型、参数、代码提交和脏工作树状态。

保存结果不得包含整篇原文、文章概括全文、完整细话题集合或原文预览。原文命中只持久化稳定
范围；需要人工核验时由本地界面按范围临时读取规范正文，普通日志不打印付费正文。

## 5. 横向比较

同一次实验在相同冻结语料、题集和参数下形成至少八个基础通道：四层分别使用 BM25 与 Dense。
分别报告 Hit@1/3/5、MRR、目标不在该层的题数、延迟、逐题提升与退化，不计算一个掩盖差异的
跨层总分。

重点分析以下问题类型：

- 模糊主题是否由概括层稳定解决；
- 明确术语是否由关键词层改善；
- 具体案例、局部机制或特殊表达是否由细话题层改善；
- 前三层遗漏的表述是否只能由原文层找回；
- 细话题或原文单元更多的长文章是否出现系统性排名优势。

累计拼接文档只作为次要消融对照，不作为新主链。它可与隔离层结果比较，用于量化 Dense 稀释、
截断和 BM25 词频竞争的影响。

## 6. 离线模拟降级

四层完整结果保存后，降级策略只读取运行记录离线重放，不重新加载模型。候选策略包括：

1. 概括层 Top1 不明确时追加关键词层；
2. 概括层 BM25 与 Dense 明显不一致时追加细话题层；
3. 前三层仍无明确领先候选时追加原文层；
4. 下一层启动后保留已有候选，以排名融合形成文章结果，不直接丢弃上一层强候选。

“不明确”优先使用层内 Top1–Top2 间隔、BM25/Dense 一致性和 Top-K 稳定性，不先写死可跨 Build
复用的绝对分数。候选阈值只能在 dev 上选择，holdout 只做一次阶段性验证。每个模拟策略同时
报告准确性、触发各层比例、平均延迟估算、最坏延迟、提升题、退化题和失败案例。

只有隔离层实验表明这些信号与失败有稳定关系后，才设计线上降级控制器。若没有可靠信号，默认
并行检索少量低成本层或让用户选择检索粒度，比伪精确的自动阈值更诚实。

## 7. 实现边界与验证

- 每层拥有独立、不可变的 Index Profile 和 Build；不同向量文本不得共用集合。
- SQLite 继续保存结构化状态，索引产物保持可重建和原子发布。
- 复用现有本地 Embedding、BM25、原文分层派生与评测结果模型，不引入工作流引擎或动态插件。
- 默认构建、检索和评测全程本地运行，不新增外部调用。
- 先用自造短文本测试单文档层、多单元聚合、无细话题文章、长文章偏置和原子范围追踪。
- 使用当前 5 道文章反查题完成冒烟与回归，但在扩大自然问题集前不据此确定线上阈值。
- 对比命令必须校验题集哈希、语料快照、层 Profile、候选深度、聚合方法和 RRF 参数，参数不一致
  时拒绝宣称为单变量 A/B。
