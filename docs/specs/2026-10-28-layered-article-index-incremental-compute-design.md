# 分层文章反查索引增量计算设计

状态：已确认并实现。

## 目标

减少新增文章或调整单层元数据后的重复 Embedding 计算，同时保持不可变 Build、历史实验复现、
失败时旧套件继续可用和最新套件原子发布。

## 设计

- 概括、关键词、细话题和原文层分别计算层级快照；套件快照继续覆盖四层全部稳定单元 ID。
- 层级快照未变化时直接复用该层 Build，新套件允许组合旧层与新层 Build。
- 变化层仍从当前完整单元集合重建 BM25 和新的 Qdrant 集合。
- Dense 构建按稳定单元 ID 查询相同 Profile 的历史就绪 Build，复用维度正确且有限的向量，只对
  未命中单元调用 EmbeddingProvider。
- Embedding Profile 改变时 profile ID 隔离历史向量，不跨模型、维度或检索配置复用。
- 四层构建全部成功后才替换 `latest-layered-suite.json`；任一层失败时不发布部分套件。

这属于增量计算而非在线索引原地增删。BM25 的全局统计仍通过完整重建保证一致性。

## 可观测性与验证

每个层级 metadata 和 CLI 输出记录 `reused_embedding_count` 与
`encoded_embedding_count`。测试覆盖单层概括变化：只有概括层产生新 Build，其他三层复用；
概括层只编码变化单元并复用未变化文章向量。既有搜索和评测通过四层单元 ID 重新计算套件
快照，不再要求四个 Build 共享同一个层级快照值。
