# 本地语料管理页设计

日期：2026-08-26

## 目标

为外部付费文章语料提供一个本地管理页，统一展示文章来源元数据、最新导入版本、当前索引
版本、分块提案和索引块数量。用户可以在页面中显式扫描语料更新、筛选和排序文章，并为
已有待审提案打开现有审核界面。

管理页不复制文章状态到新的汇总表。`articles`、`article_versions`、`chunk_proposals`、
`approved_manifests`、`topic_chunks` 和 `index_builds` 继续作为事实来源，页面数据由查询服务
实时聚合。第一版不把 Codex 或其他外部模型调用迁入网页。

## 启动与安全边界

新增命令：

```powershell
xifeng corpus manage
```

命令启动只绑定 `127.0.0.1` 随机端口的临时 HTTP 服务，生成高熵会话令牌并默认打开浏览器。
可使用 `--no-open` 只打印地址。页面不加载远程脚本、样式、字体或统计资源，所有数据与操作
均通过带令牌的本机同源接口完成。

浏览器不接触数据库路径、SQL 或外部语料绝对路径。服务端只暴露固定的文章聚合字段、扫描
操作和审核会话入口，不提供任意文件读取或通用数据库接口。

## 来源元数据

复用 `articles` 表并增加可空字段：

- `captured_at`：外部 `index.json` 中该文章的 `captured_at`，表示抓取或导出时间；
- `published_at`：配套 HTML 中的微信原始发布时间，优先读取 `ori_create_time`；
- `source_modified_at`：规范 Markdown 文件的文件系统修改时间；
- `source_size_bytes`：规范 Markdown 文件大小；
- `source_character_count`：外部 `index.json` 的 `chinese_char_count`，只作为来源统计；
- `metadata_synced_at`：最近一次成功扫描并同步该行来源元数据的时间。

现有 `created_at` 继续表示首次导入数据库的时间。`published_at` 只读取配套 HTML 中的结构化
时间字段，HTML 正文不作为第二份正文索引；缺少可靠元数据时保持为空。页面分别标注“发布
时间”“抓取时间”和“文件修改时间”，不以本地时间冒充原始发布时间。

扫描时解析 `index.json` 的稳定 ID 与上述元数据。元数据变化但 Markdown 正文哈希不变时，
只更新 `articles`，不创建新正文版本，也不触发重新分块或索引。缺失、格式错误的可选元数据
保持为空，不影响正文导入；稳定 ID 与文件映射冲突仍按现有规则终止扫描。

## 文章状态聚合

每一行代表一篇 `Article`，不代表一个 `ArticleVersion`。查询服务分别计算：

- 最新来源版本：该文章按 `created_at` 和 ID 排序的最新版本；
- 当前索引版本：状态为 `indexed` 的最新版本；
- 处理状态：最新来源版本的状态；
- 待审提案数：最新来源版本中 `pending_review` 的提案数量；
- 全部提案数：最新来源版本的提案数量；
- 索引块数：当前索引版本关联的 `topic_chunks` 数量；
- 有待处理更新：存在当前索引版本，且其 ID 与最新来源版本不同；
- 已索引：存在当前索引版本且至少有一个索引块；
- 来源状态：`articles.active` 为真时是“存在”，否则是“缺失”。

增量构建为保证旧索引可用，允许同一文章暂时同时存在旧索引版本和新待处理版本。因此管理页
不把 `article_versions.active` 当成唯一当前版本标志，而是明确展示“最新来源版本”和“当前索引
版本”，避免把安全切换期间的双版本误报为重复文章。

页面顶部统计活动文章总数、已索引文章数、待处理文章数、待清洗审核数和来源缺失数，并显示
“已索引文章 / 活动文章”的覆盖率。

## 页面与交互

页面由顶部统计区、操作区和文章表格组成。

操作区提供：

- “扫描语料更新”按钮；
- 标题或文章 ID 关键词搜索；
- 处理状态筛选；
- 已索引、未索引、有更新待处理、来源缺失等快捷筛选；
- 按发布时间、抓取时间、文件修改时间、首次导入时间、标题和处理状态排序。

表格显示：标题、发布时间、抓取时间、文件修改时间、最新状态、提案数、索引块数、最新来源
版本和当前索引版本。长 ID 使用省略显示并保留完整 `title` 提示。默认按发布时间倒序；空时间
排在最后。

点击“扫描语料更新”后，按钮进入忙碌状态并防止重复请求。服务端在单个数据库事务内调用
现有 `scan_corpus`，成功后返回解析后的绝对语料目录、发现文章数、排除、新增、正文修改、
元数据更新、未变化、缺失和待清洗审核数量。页面显示结果并重新加载表格。扫描失败时事务
回滚，页面保留原列表并显示不含正文的错误。

若最新来源版本存在待审提案，行操作提供“审核”按钮。一个版本存在多个待审提案时，先显示
提案选择框，列出 provider、model、Prompt 版本和创建时间。选择后，管理服务为该提案创建
一个内存审核会话，并在新标签页打开现有审核界面。审核页继续负责草案保存、批准、更新索引
和关闭审核会话。完成后管理页通过“刷新”或再次加载看到新状态。

管理页可为最新 active 且处于待分块或待审核状态的单篇文章启动固定的 Codex AI 分块，并在
逐次展示外发范围、获得二次确认后生成并列提案。详细交互与安全边界见
[`2026-09-15-corpus-dashboard-ai-chunking-design.md`](2026-09-15-corpus-dashboard-ai-chunking-design.md)。

## 接口与服务结构

管理服务提供以下固定接口：

- `GET /api/articles`：返回聚合文章列表和顶部统计；
- `POST /api/scan`：显式扫描语料目录并返回扫描摘要；
- `POST /api/reviews`：为指定待审 proposal 启动独立临时审核服务并返回本地 URL；
- `POST /api/shutdown`：停止管理服务，仅在显式点击“关闭管理页服务”后执行。

筛选与排序第一版在浏览器内完成，因为语料规模约百篇；后端始终返回相同的受限聚合结构。
管理页和审核页使用独立随机令牌，审核会话还固定绑定一个 version/proposal 组合。任何 proposal
必须存在、属于指定最新来源版本且仍为 `pending_review`，否则拒绝创建审核会话。

为避免把两个 HTTP 服务生命周期耦合得过深，第一版“审核”操作启动一个现有的独立随机端口
审核服务，并返回其 URL；管理服务保存子服务引用，在自身退出时关闭仍存活的审核子服务。
审核完成后其“关闭审核服务”按钮只停止对应子服务，不关闭管理页。

## 扫描状态与增量规则

扫描继续遵守现有增量规则：

- 新文件创建文章和待处理版本；
- 规范正文变化创建新版本，旧活动索引在新版本完整批准和建库前继续可用；
- Markdown 或清洗结果未变化时不重复生成版本；
- 仅来源元数据变化不触发分块或索引；
- 文件缺失时文章标记为 inactive，不物理删除历史版本；
- 扫描不得自动生成提案、批准清单或索引。

`ScanSummary` 增加 `metadata_updated`，它只统计正文未变化但至少一个来源元数据发生变化的文章。
新增文章和正文修改文章即使同时写入元数据，也只计入 `added` 或 `modified`，避免重复计数。

## 错误处理

- 语料目录不存在或没有顶层 Markdown：扫描失败并显示解析后的目录错误，不建立空状态；
- `index.json` 的稳定 ID 映射冲突：整个扫描事务回滚；
- 单篇可选元数据缺失或格式错误：保留空值并继续扫描；
- 重复点击扫描：前端禁用按钮，后端使用进程锁拒绝并发扫描；
- 创建审核会话时状态已改变：返回冲突并要求刷新列表；
- 浏览器自动打开失败：服务继续运行并在终端输出可复制地址；
- 管理服务关闭：一并停止仍存活的审核子服务，不修改数据库状态。

## 测试与验收

自动测试只使用自造 Markdown、临时 `index.json` 和临时 SQLite，至少覆盖：

- 迁移为现有数据库增加可空来源元数据列；
- 扫描导入 `published_at`、`captured_at`、文件修改时间、大小和来源字符数；
- 仅元数据变化增加 `metadata_updated`，且不创建新版本或段落；
- 新增、正文修改、未变化、缺失和失败回滚仍符合既有增量规则；
- 聚合查询正确区分最新来源版本与当前索引版本；
- 状态统计、提案数、索引块数和覆盖率正确；
- 管理接口要求有效令牌，扫描接口不接受 GET；
- 扫描按钮忙碌状态和结果刷新逻辑存在；
- 只有仍待审且版本匹配的提案可以创建审核会话；
- 页面无远程资源、无正文日志、无任意路径或 SQL 接口；
- 关闭管理服务不会修改文章、批准清单或活动索引。

人工验收使用当前本地语料：确认页面显示全部活动与缺失文章，默认按发布时间倒序且空时间
排在最后，可按状态和索引情况筛选，扫描结果与命令行 `corpus scan` 的分类一致，并能为一个
待审提案打开现有审核界面。验收不得批量生成提案或批准任何现有提案。

## 非目标

第一版不包含：

- 从管理页选择或批量调用任意分块模型；单篇固定 Codex AI 分块属于显式支持的例外；
- 自动扫描、文件系统常驻监听或定时任务；
- 编辑外部语料文件或 `index.json`；
- 批量分块、批量批准或批量索引；
- 人工标签体系、文章主题分类或“道/术”自动判断；
- 远程访问、多用户账户或权限系统；
- React/Vue、前端构建链或通用后台管理框架。
