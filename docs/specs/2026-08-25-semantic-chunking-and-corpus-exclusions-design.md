# 语义优先分块与单篇语料排除设计

状态：已确认，作为 V0 MVP 设计的增补。

## 1. 背景与目标

当前语料既包含约一万字以上的长文章，也包含作者早期约三千字的完整付费文章。
文章长度不能可靠判断正文是否完整，也不应决定话题块数量。

本次调整实现两个目标：

1. 只排除已由用户确认不完整的文章，不按字数批量排除短文章；
2. 话题块按语义边界划分，不再追求固定块数或目标字符数。

外部语料目录仍保持只读。

## 2. 可配置的单篇排除

在 `corpus` 本地配置中增加稳定文章 ID 列表：

```yaml
corpus:
  excluded_article_ids:
    - sn:2a602cf6b0a62299d0f31f4245bf6d4a
```

默认列表为空。真实语料的排除项写入 Git 忽略的 `config.local.yaml`，示例配置只展示
空列表，避免把具体私有语料清单固化为应用默认值。

扫描仍先统计顶层 Markdown 文件并解析 `index.json` 中的稳定 ID，然后应用排除列表：

- 排除项不生成新的规范正文、段落或分块提案；
- 数据库中已经存在的排除文章及活动版本被标记为 inactive；
- 排除项不计为缺失文章，扫描结果单独报告排除数量；
- 索引继续只选择活动且已批准的版本，因此排除项不会进入索引；
- 从配置中移除 ID 后，下次扫描按普通新增或恢复流程重新处理该文件。

若配置的 ID 无法在当前 `index.json` 和语料文件之间匹配，扫描给出明确警告但不中断，
便于发现过期或拼写错误的排除项。

## 3. 语义优先分块

分块提示词改为“使用能完整表达文章结构的最少必要话题块”：

- 主题、论证对象、核心观点或论述阶段明显转换时建立新块；
- 同一条连续论证保持在同一块中，不因篇幅而机械拆分；
- 短而连贯的文章允许只有一个话题块；
- 不向模型指定通常块数、目标字数或最大字数；
- 所有规范段落仍须按顺序恰好覆盖一次。

结构化输出保持现有 `TopicProposal` Schema，不修改数据库结构。程序继续执行以下硬校验：

- 至少存在一个话题块；
- 段落编号有效；
- 块之间连续、无重叠；
- 所有段落恰好覆盖一次；
- 标题、概括和关键词非空。

原先的“偏离 4–6 块”“少于 800 字符”和“大于 6000 字符”警告全部移除。
语义质量无法由字符阈值可靠判断，仍通过 JSON/Markdown 审核产物由用户确认。

提示词版本升级，以免旧提案缓存被误认为新策略的输出。已有提案和批准清单保持不可变；
采用新策略时生成新的提案 ID，不覆盖历史结果。

## 4. 状态与数据流

```text
顶层 Markdown + index.json
  -> 解析稳定文章 ID
  -> 命中 excluded_article_ids？
       -> 是：停用已有记录，计入 excluded
       -> 否：确定性清洗与版本识别
  -> pending_chunking
  -> 本地模型按语义提出最少必要话题块
  -> 结构与覆盖校验
  -> pending_review
  -> 用户审核批准
  -> BM25 索引
```

排除配置只影响语料准入，不改变清洗、批准清单或索引结构。

## 5. 错误处理与可审计性

- 排除配置格式不合法时启动失败，不静默忽略；
- 同一 Markdown 无法解析稳定 ID 时沿用已有后备 ID 规则，但不能错误匹配 `sn` 排除项；
- 未匹配的排除 ID 在扫描摘要中显示；
- 被排除文章的旧提案可以保留用于审计，但其文章版本 inactive，不能批准或入索引；
- 不删除数据库记录、审核文件或外部原文。

## 6. 验证

自动化测试至少覆盖：

1. 空排除列表保持现有扫描行为；
2. 指定文章 ID 后，该文章计入 excluded 而非 added/missing，且不会进入待分块集合；
3. 已存在文章被排除后，其文章和活动版本被停用；
4. 从配置解除排除后，文章能够再次进入正常扫描流程；
5. 单话题提案通过 Schema 与覆盖校验；
6. 提示词不包含固定块数和字符目标；
7. 分块警告不再按字符数或常见块数触发；
8. 已排除版本不会进入 BM25 索引。

本机验收使用一篇约三千字的完整短文章和一篇长文章。审核重点是是否在真实语义转换处
切分、连续论证是否被保留完整，以及人工是否需要大量修改边界；字数只作为观察数据，
不作为通过条件。
