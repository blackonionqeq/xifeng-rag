# 文末付费文章目录清洗加固设计

状态：已确认设计，待实施。

## 1. 问题与目标

近期 5 篇由 Codex CLI 辅助生成的分块提案中，规范正文都残留了部分文末付费文章目录。
模型在其中 3 篇中把目录单独切块，在另外 2 篇中把目录并入最后一个正文话题。模型表现差异
暴露了上游清洗缺陷：现有清洗器从较晚出现的“备用号”目录标记开始截断，没有回溯到整段
目录的最早入口；部分带 Markdown 强调符号或同行多链接的格式也没有被稳定识别。

本次目标是让付费文章目录在确定性清洗阶段从规范正文完整移除，不再参与分块、文章概括、
BM25、Embedding 或后续图关系抽取。无法高置信度判断时，流程必须停在清洗审核，不能把判断
责任静默转交给分块模型。

本次不抽取、保存或索引目录中的文章关系，也不建设通用附录分类系统。

## 2. 方案选择

采用“确定性清洗为主、分块防御为辅”的方案：

1. 清洗器使用目录语义、尾部位置和链接密度的组合信号识别完整目录区间；
2. 高置信度时自动删除整个尾部目录；
3. 信号不足或相互冲突时标记 `needs_cleanup_review`，禁止生成分块提案；
4. 分块 Prompt 和本地提案检查只作为第二道防线，不能替代清洗决定。

不采用只改 Prompt 的方案，因为模型即使把目录单独成块，当前提案默认仍会将它纳入索引；
也不采用只按链接数量截断的方案，因为正文末尾的正常引用或参考资料可能被误删。

## 3. 确定性目录检测

### 3.1 仅用于检测的文本归一化

目录检测对每个原始行构造一个不改变源位置的匹配视图：

- 忽略 Markdown 粗体、斜体等强调定界符；
- 保留可见文字；
- 统计每行 Markdown 链接数量以及是否为独立链接行；
- 不在规范正文中使用这个匹配视图，也不改写外部语料。

这样可以统一识别“所有的付费文章”被多段 `**` 拆开的实际格式，以及一行包含多个目录链接
后再接目录标题的格式。

### 3.2 高置信度条件

自动删除必须同时满足以下三类信号：

- 目录语义：出现“全部/所有付费文章”“付费文章链接”“整理出来”“已读全部付费文”等明确
  引导语，或现有的目录、合集、备用号标记；
- 链接结构：引导语之后存在至少 5 个链接，并分布在至少 3 个链接行，或者出现等价的高密度
  同行链接结构；
- 尾部连续性：候选区之后直到文件结尾以目录标题、账号切换提示、独立文章链接和少量目录说明
  为主，不出现明显恢复正文论述的长段落。

普通正文中的单个链接、正文内相关文章举例和短参考列表不能单独触发自动删除。

### 3.3 找到完整起点

检测器先从文章尾部确认一个高置信度目录区域，再在该连续区域内向前回溯，选择最早的目录
引导语作为截断点。后续“大号、小号、备用号”等子目录共同属于同一个移除区间，不能从中间
某个子目录开始截断。

若能够确认尾部链接目录存在，但无法确定最早引导语，清洗结果标记为待审核并保留原文，避免
自动多删。审核仍复用现有 `corpus resolve-cleanup` 流程。

## 4. 分块阶段防御

默认分块指令增加明确边界：清洗后若仍意外出现文章目录、推广区或相关文章链接列表，它不属于
正文顶层话题，不能并入最后一个实质话题。

本地在调用模型前再次检查清洗后的尾部结构。若仍满足可疑目录条件，直接拒绝生成提案并提示先
处理清洗审核。该检查不依赖模型返回的标题或概括，因此不会因模型措辞不同而失效。

这道防线只处理清洗器漏网或旧版本数据，不创建“目录话题块”，也不改变所有正文单元必须被话题
提案连续覆盖的协议。

## 5. 版本与存量处理

- 提升 `CLEANER_VERSION`，确保相同源文件会用新规则重新规范化；
- 先提供或执行只读 dry-run，比较每篇文章的新旧规范正文哈希、截断起点和删除字符数；
- dry-run 只显示文章标识、判断状态和数值，不输出付费正文或目录标题；
- 高置信度结果才进入正常扫描更新，歧义结果进入 `needs_cleanup_review`；
- 规范正文变化后创建新文章版本，旧批准版本继续可用，直到新版本完成分块、审核和索引发布；
- 当前发现问题的 5 篇均为 `pending_review`，其旧提案不得继续批准。新规范版本需要重新生成
  分块提案；外部 Codex CLI 重试仍遵守单篇、显式触发和逐次确认的隐私规则。

本次不自动迁移旧提案边界，因为旧提案基于包含目录的不同规范正文，迁移会破坏不可变版本和
审核可追溯性。

## 6. 错误处理与可审计性

清洗结果继续保存精确 `removed_ranges`、警告和清洗器版本。新增诊断只记录信号类型、链接计数、
行数和候选范围，不记录完整正文或链接 URL。

下列情况必须进入人工审核：

- 明确目录语义但链接数量不足；
- 尾部链接密集但没有明确目录语义；
- 候选目录之后又出现疑似正文论述；
- 多个候选起点无法确定哪一个是完整目录的最早入口。

## 7. 测试与验收

测试仅使用自造短文本，覆盖：

- 多账号连续目录回溯到最早入口；
- Markdown 强调符号拆开目录关键词；
- 一行多个链接后紧接下一子目录标题；
- 目录前有一至三句说明文字；
- 正文中的单个引用不截断；
- 正文末尾的短参考链接列表不截断或进入人工审核；
- 目录后恢复正文时进入人工审核；
- 分块前发现残留可疑目录时拒绝调用模型；
- 清洗器版本升级后新增、修改、未变化、缺失及失败回滚语义保持正确。

真实语料验收先运行全量只读 dry-run。验收标准为：近期 5 篇都定位到同一目录区的最早入口；
没有正文正常引用被自动截断；所有低置信度案例都进入审核而不是继续分块。随后运行 Ruff、Pyright
和完整 pytest。
