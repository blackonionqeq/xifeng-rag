# 检索评测运行与结果工作台设计

状态：已实现 v0.1（2026-10-20）。

## 1. 目标

在现有 `xifeng eval curate` 本地工作台中补齐“冻结题集 → 运行检索评测 → 查看结果 → 与历史
基线比较”的闭环。页面服务于开发实验和面试展示，但继续以现有评测核心与
`evaluation_runs` 为唯一计分和持久化实现。

首版只覆盖证据检索评测。端到端回答与引用评测继续使用独立命令、外发披露和运行记录，不与
本页指标混合。

## 2. 页面结构

评测工作台增加两个顶层视图：

- “题集策展”保留现有问题录入、证据审核和冻结流程；
- “运行结果”提供运行表单、历史运行、汇总指标、分组指标、逐题诊断和两次运行对比。

运行表单只列出冻结题集及语料快照相同的可用 Index Build。默认建议 `dev`、Hybrid、K=5 和
本地 Reranker；BM25、Dense 与不重排 Hybrid 仍可显式选择。一次只运行一个检索评测后台任务，
工作台关闭时不得遗留仍在运行的任务。

`holdout` 必须在页面再次确认其只用于阶段性最终验证，不能用结果反复调参。服务端同时验证
确认字段，不能只依赖浏览器提示。

## 3. 结果与对比

历史运行直接读取 `evaluation_runs`，不迁移或复制已有数据。结果分为：

1. Precision@K、Recall@K、MRR、nDCG@K、证据覆盖率、平均和 P95 延迟；
2. 题集哈希、语料快照、Build、Profile、模式、Reranker、代码提交和 dirty 状态；
3. 按难度与题目来源分组的指标；
4. 每题金标准范围、Top-K 候选、来源、阶段分数、排名、覆盖和延迟。

候选正文只在用户打开运行详情时，根据保存的 Chunk ID 从本地 SQLite 按需读取。正文不写入
`evaluation_runs.details_json`，也不进入普通日志。

选择历史基线后，只有题集内容哈希、语料快照、split 和 K 全部相同时才计算指标差值。模式、
Build、Profile 和 Reranker 可以不同，因为它们正是实验变量；页面始终展示两边的运行身份，
由用户遵守单变量实验纪律。条件不兼容时只展示原因，不输出差值。

## 4. 组件边界

- `evaluation.py` 继续负责运行、计分与持久化；
- `evaluation_results.py` 只负责安全查询、按需补充本地候选信息和兼容性比较；
- `evaluation_ui.py` 负责输入校验、单任务异步编排和本地 HTTP API；
- `eval curate` 独立入口和项目控制台入口注入同一个普通评测运行函数，负责按配置加载和关闭
  Embedding/Reranker，两个入口的页面能力保持一致。

页面不复制检索实现，不增加动态评测插件、外部服务或前端构建链。

## 5. 验收

- draft 题集不能运行，Build 快照不匹配时拒绝；
- dev 可异步运行，holdout 未确认时拒绝；
- 运行完成后出现在历史列表并可查看逐题结果；
- 兼容运行显示汇总差值，不兼容运行明确说明原因；
- 运行记录仍不包含原文，详情接口只在本地按需读取；
- 页面保持回环绑定、令牌校验、严格 CSP 和零远程资源。
- 从 `xifeng eval curate` 或 `xifeng workbench` 启动时都能运行检索评测。
