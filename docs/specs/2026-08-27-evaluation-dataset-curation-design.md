# 本地评测集策展与 Codex 辅助设计

日期：2026-08-27

## 目标

为当前 BM25 基线建立可复现的本地评测集闭环：人工录入真实问题，选择一篇已索引文章，
由 Codex CLI 在逐次披露和确认后生成候选答案、答案要点与证据范围，再由人工修改、确认并
冻结。正式评测根据稳定的文章版本与原子单元范围动态映射相关 TopicChunk，不再把易变的
`topic_chunk_id` 作为金标准。

第一批只制作 6–8 道单篇、可回答的 `pilot` 开发题，用于验证流程。流程稳定后另建正式
benchmark，目标规模为约 12 道 dev 与 8 道 holdout。第一版不生成问题，不实现跨文章题、
整篇总结评分、批判性阅读评分、外部事实核查或批量外发。

## 独立评测工作台

新增命令：

```powershell
xifeng eval curate
```

命令启动独立的本地评测工作台，只绑定 `127.0.0.1` 随机端口，使用高熵随机令牌、同源
接口、严格 CSP、受限请求体和本地静态资源。第一版继续使用 Python 标准库 HTTP 服务与原生
HTML、CSS、JavaScript，不引入 FastAPI 或前端构建链。

页面分为题目列表、编号原子单元以及答案与证据审核区。用户可以：

- 创建或选择 draft 数据集；
- 人工原样录入问题并选择一个已索引文章版本；
- 在正文中选择一个或多个连续原子单元范围；
- 编辑参考答案、答案要点与证据；
- 逐题调用 Codex 辅助判断；
- 接受、修改或拒绝 Codex 候选；
- 标记题目已人工审核并冻结完整数据集。

评测工作台与语料管理页、分块审核页保持独立生命周期，不在语料管理服务中加入外部模型
长任务。

## 组件边界

实现分成三个边界清晰的部分：

1. 评测集核心负责 draft 数据集、问题、证据、AI 候选、人工审核和冻结规则；
2. 评测工作台负责受限本地 API、页面状态、披露确认和异步 AI 任务；
3. 检索评测运行器读取冻结数据集，把证据范围映射到被测 Index Build，并计算指标。

现有 `CodexCliClient` 已能接收任意 Prompt 和 JSON Schema，但位于分块模块且包含分块专用
命名与提示。将隔离执行提取为通用 Codex CLI 客户端；分块和评测分别提供自己的 Prompt、
Schema 与 Pydantic 校验。两条路径都保持以下参数：

```text
ephemeral
read-only sandbox
ignore user config
ignore rules
skip git repository discovery
empty temporary directory
stdin input
JSON Schema output
```

## 数据模型

### EvaluationDataset

评测集保存名称、版本、用途 `pilot/benchmark`、状态 `draft/frozen`、冻结内容哈希、冻结时间和
语料快照。冻结后不可修改；后续调整必须克隆为新的 draft 版本。

### EvaluationSnapshotArticle

冻结时保存完整活动索引包含的文章 ID、文章版本、规范正文哈希和批准清单 ID。快照不能只
引用某个 Index Build，因为同一语料需要公平比较不同 Index Profile。正式运行要求被测索引
的语料成员与冻结快照完全一致。

### EvaluationQuestion

问题保存人工原样录入的文本、`dev/holdout`、范围 `article`、目标文章及版本、可回答性、
人工确认后的参考答案和审核状态。首批 pilot 只允许 `dev`、`article` 和可回答题。

### EvaluationEvidence

每条证据保存：

```text
question_id
article_id
article_version
start_paragraph
end_paragraph
claim_group
claim_text
```

一道题允许多个答案要点；一个答案要点允许多个不连续证据范围。`claim_group` 标识范围共同
支撑的答案要点。当前检索指标使用全部证据映射出的相关块并集，后续可以继续计算答案要点
覆盖率。

### EvaluationAIProposal

每次成功的 Codex 调用保存解析后的候选答案、答案要点、证据范围、provider、模型、Prompt
与 Schema 版本、状态和创建时间。只保存结构化候选，不保存完整外发请求、文章副本、Codex
原始响应、stdout 或 stderr。候选可被接受、拒绝或保留待审；接受只复制到仍可编辑的人工
草案，不直接完成审核或冻结。

### EvaluationRun

沿用现有运行记录并补充冻结题集哈希、语料快照、Index Build、Index Profile、K、代码提交
ID、工作区 dirty 状态、汇总指标与逐题结果。运行详情不保存付费正文。

## Codex 辅助流程

问题必须由人工创建，Codex 不生成或改写问题。保存问题并选择文章后，用户点击“AI 辅助
判断”，页面向服务端请求一次权威披露。弹窗至少显示：

```text
问题
文章标题、ID、版本
规范正文哈希
清洗后字符数
原子单元数
provider: codex-cli
model: gpt-5.6-terra
最大请求次数: 1
将外发问题、文章标题、完整清洗正文及编号
```

只有用户在弹窗中再次点击“确认并发送”后才启动 Codex。披露凭据绑定问题内容、文章版本、
模型和一次性随机值；问题或文章改变后旧凭据失效且不得重放。每次失败或重新生成都必须重新
披露和确认，不提供批量确认或永久允许。

Codex 每次只接收用户明确选择的一篇文章，且不能看到 BM25 或其他检索结果。固定结构化输出
包括：

```text
candidate_answer
answer_points[]
  claim
  evidence_ranges[]
    start_paragraph
    end_paragraph
  uncertainty
```

服务端验证范围存在、顺序正确、属于当前文章版本且至少有一个答案要点和证据范围。程序不得
猜测或修复非法范围。

Codex 调用作为页面内异步任务运行，浏览器轮询状态。同一工作台最多同时运行一个任务。
只有成功且结构校验通过后才保存候选；进程重启不会自动重发。AI 任务运行时拒绝关闭服务，
避免留下失控子进程。

## 人工审核与冻结

人工接受候选后可以编辑答案和要点，也可以在编号正文中重新选择证据范围。保存时服务端只
信任问题、答案文本、要点和单元编号，不信任浏览器提交的正文或身份字段。

每道题必须显式标记“人工审核完成”。冻结前验证：

- 每道题均为人工录入；
- 目标文章版本属于待冻结语料快照；
- 每道可回答题至少有一个答案要点和证据范围；
- 所有范围有效且经过人工确认；
- 不存在仍待处理的 Codex 候选；
- 快照成员、正文哈希和批准清单完整。

冻结在一个数据库事务中写入快照、冻结时间和题集内容哈希。失败时整体回滚并保持 draft。

首批 6–8 题使用 `pilot`。pilot 冻结并跑分后只作为探索结果，不得原地升级成正式 holdout。
正式 benchmark 必须新建，冻结后不可因新增文章或新检索结果静默修改。

## 检索评测

正式运行只接受冻结数据集。用户可显式选择 Index Build；未指定时使用活动索引。被测索引的
语料快照必须与题集快照完全一致，否则拒绝运行。

金标准证据通过文章版本和原子单元范围映射：TopicChunk 与证据范围有交集时视为相关候选；
一个证据范围跨越多个块时，这些块均为相关块。当次映射出的块 ID 写入运行详情，不写回冻结
题集。

第一版报告：

- Precision@K；
- Recall@K；
- MRR；
- nDCG@K；
- evidence coverage@K；
- 平均查询延迟与 P95。

`evidence_coverage@K` 计算 Top-K 返回块覆盖的金标准证据原子单元比例，用于降低切块边界变化
对评测的影响。

运行阶段不调用 Codex、Generator 或其他外部模型，也不把原文写入普通日志或运行详情。

## 错误处理

- 问题或文章在披露后变化：确认凭据失效并要求重新披露；
- 文章版本不再属于当前索引：拒绝调用并要求刷新；
- Codex 未登录、超时、异常退出或输出非法：不保存候选，不自动重试；
- 证据越界、倒序、无证据或跨文章：拒绝整份候选；
- 人工草案非法：保留页面编辑内容并返回逐项错误；
- 冻结失败：事务回滚；
- 冻结后编辑、AI 调用或重新审核：拒绝并提示克隆新版本；
- 快照与 Index Build 不一致：拒绝运行且不创建 EvaluationRun；
- AI 任务运行中关闭服务：拒绝关闭并提示等待。

终端和 HTTP 错误不得包含规范正文、完整 Prompt、外部原始响应、API 密钥或 Codex 输出正文。

## 测试与验收

自动测试只使用自造短文本、临时 SQLite 与假的 Codex 子进程，至少覆盖：

- 迁移保留既有文章、块、索引和评测运行；
- draft、pilot、benchmark、dev、holdout 与 frozen 状态约束；
- 单篇问题、多答案要点和多段证据的创建、编辑、审核与冻结；
- 冻结内容哈希与快照成员稳定；
- 稳定证据到不同 Chunk 边界的映射；
- 原有检索指标与 evidence coverage；
- 快照不匹配时拒绝运行；
- 披露内容完整、一次性确认不可重放；
- Codex CLI 隔离参数和 Schema 输出；
- Codex Prompt 不包含检索结果；
- 原始请求、正文和外部原始输出不进入数据库或日志；
- 无令牌、错误令牌、过大请求与并发 AI 调用被拒绝；
- 页面不加载任何远程资源。

人工验收使用 WSL Ubuntu 中的 `agent-browser`。首次真实 Codex 验收必须由用户在页面确认一篇
文章；自动测试和页面加载不得触发真实外发。

## 非目标

第一版不包含：

- AI 生成或改写问题；
- 多篇文章或整库一次性发送给 Codex；
- 批量 AI 辅助、永久授权或自动重试；
- 跨文章题、时间演变题、整篇总结和批判性阅读评分；
- 外部事实核查或自动评委；
- corpus discovery 正式计分；
- Generator、Dense、RRF 或 Reranker；
- 远程访问、多用户权限或前端框架。
