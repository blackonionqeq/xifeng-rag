# 本地工作台设计

状态：已确认并实施 v0.1。

## 1. 目标

提供单一的本地页面，集中发现并启动现有浏览器界面，同时列出常用一次性命令，降低记忆 CLI
层级与参数的成本。入口命令为 `uv run xifeng workbench`。

## 2. 页面范围

第一版管理三个一级页面：

- 演示台：文章反查和带引用问答；
- 语料管理：扫描、状态查看、分块与细话题审核入口；
- 评测策展：问题、证据标注、审核与冻结。

分块审核和细话题审核继续由语料管理页按具体文章启动。检索评测、回答评测、索引构建和环境
检查属于一次性命令，工作台只展示用途明确、可复制的命令；正式评测命令自动填入最新冻结
benchmark 的 ID，没有可用题集时显示占位符。工作台不提供任意命令执行器。

## 3. 服务生命周期

工作台只监听 `127.0.0.1` 随机端口并使用随机令牌。三个服务按需在同一进程内的独立随机端口
启动；每类最多一个实例。页面展示未启动、启动中、运行中和失败状态。运行中再次操作只打开
现有地址。工作台可以停止单项服务，关闭时停止由它启动的全部服务并释放模型资源。

演示台的 Embedding provider 延迟到点击启动时加载。原有 `demo`、`corpus manage` 和
`eval curate` 命令继续可独立使用。

## 4. 文档入口

README 集中列出四个浏览器入口，CLI 工作流用表格区分常驻页面、从属审核页和一次性任务。
工作台页面显示同样的职责说明及常用命令，避免读者跨多个章节寻找入口。

## 5. 非目标

- 在网页中运行任意 CLI 命令；
- 后台任务队列、日志聚合或进度恢复；
- 合并现有页面的路由和静态资源；
- 自动执行索引构建、外部模型调用或 benchmark；
- 公网部署和多用户管理。
